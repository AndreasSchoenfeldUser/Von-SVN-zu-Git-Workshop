Mit KI vertiefen

VERSTEHEN

Was gehört in eine gute Merge-Request-Beschreibung? Erstelle eine Vorlage für GitLab mit Abschnitten für Zweck, Änderungen, Tests und offene Fragen, und sage, wo die Vorlage im Repository liegen muss.

ÜBEN

Schreibe eine Spring-Boot-Klasse von höchstens 40 Zeilen, die ohne weitere Klassen kompiliert und genau drei Schwächen enthält; gib sie vollständig aus, nicht als Diff. Ich schreibe Review-Kommentare; nenne die Schwächen erst danach und bewerte Inhalt und Ton.

ÜBERTRAGEN

Welche Regeln für Merge Requests passen zu einem Team mit fünf Personen: Größe, Freigaben, Pipeline-Pflicht, Antwortzeit? Begründe jede Regel und nenne die GitLab-Einstellung, mit der sie sich durchsetzen lässt, samt nötiger GitLab-Stufe.

Für Claude und ChatGPT. Antworten mit den Referenzen abgleichen, keinen vertraulichen Code eingeben.

Der Übungs-Prompt lässt die KI den Code erzeugen; so muss niemand Firmencode einfügen. Im Test enthielt die Klasse meist mehr als die verlangten drei Schwächen; zusätzliche Funde sind kein Fehler der Teilnehmenden. Verpflichtende Freigaben und Code Owners gibt es erst ab GitLab Premium.
