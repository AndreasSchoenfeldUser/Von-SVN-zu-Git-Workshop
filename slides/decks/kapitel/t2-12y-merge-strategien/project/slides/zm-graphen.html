Merge-Commit oder Squash: Was in main sichtbar bleibt

Merge-Commit mit --no-ff

A

B

C1

C2

M

main

feature

Die einzelnen Schritte bleiben erhalten, M zeigt Anfang und Ende der Aufgabe.

Squash mit --squash

A

B

C1

C2

S

main

feature (löschen)

Der neue Commit S enthält alles. Die Verbindung zum Branch geht verloren.

Nach einem Squash hält git branch -d den Branch für nicht gemergt. Er wird mit -D gelöscht.

Von SVN zu Git · Tag 2

Beim Merge-Commit hat M zwei Vorgänger, beim Squash hat S nur einen. Für Git sind C1 und C2 deshalb nie in main angekommen. Wer nach dem Squash auf dem alten Branch weiterarbeitet und erneut mergt, bekommt Konflikte mit den eigenen Änderungen. Darum: Branch nach dem Squash löschen.
