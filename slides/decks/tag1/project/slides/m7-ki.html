Modul 07 · Der kaputte Freitag

Mit KI vertiefen

VERSTEHEN

Erkläre, wie git bisect funktioniert und wann es schneller zum fehlerhaften Commit führt als git log und git blame, und wann umgekehrt git log -S oder git blame -L schneller sind. Rechne vor, wie viele Schritte bei 500 Commits nötig sind.

ÜBEN

Simuliere ein Java-Projekt mit zehn Commits, in dem sich ein Fehler versteckt; erfinde die Autoren und halte die Ausgaben stimmig. Ich frage nach git log, git show und git blame. Gib keine Hinweise und nenne die Lösung erst, wenn ich den Commit benenne.

ÜBERTRAGEN

Wie kombiniere ich git bisect mit einem automatisierten Test wie mvn test? Zeige den Ablauf mit git bisect run, erkläre die Exit-Codes und wie ich Commits überspringe, die nicht bauen oder den Test noch nicht enthalten.

Für Claude und ChatGPT. Antworten mit den Referenzen abgleichen, keinen vertraulichen Code eingeben.

Von SVN zu Git · Tag 1

Der Übungs-Prompt macht aus der KI eine Spielleitung für weitere Runden „Der kaputte Freitag“. Simulierte Ausgaben sind oft formal unstimmig (Hunk-Header, blame-Zuordnung); für die Übung ist das unerheblich. Bei 500 Commits sind höchstens neun Schritte nötig. Bisect-Skripte aus KI-Antworten vor dem Einsatz prüfen: Im Test verhinderte set -e den Sprung zu exit 125.
