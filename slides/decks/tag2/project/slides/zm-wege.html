Zusatzmodul · Merge-Strategien

Vier Wege, einen Branch zu integrieren

MERGE-COMMIT

--no-ff

Ein Merge-Commit klammert den Branch, auch wenn ein Fast-Forward möglich wäre.

FAST-FORWARD

--ff-only

main rückt nur vor. Ist main weitergelaufen, bricht Git ab.

SQUASH

--squash

Alle Änderungen des Branches werden zu einem einzigen neuen Commit.

REBASE

rebase

Die Commits werden auf den neuen Stand von main gesetzt, dann rückt main vor.

Ohne Option macht git merge einen Fast-Forward, wenn das möglich ist, und sonst einen Merge-Commit.

Von SVN zu Git · Tag 2

Fast-Forward und 3-Way-Merge kennen die Teilnehmenden aus Modul 06, Rebase aus Modul 12. Neu sind die Optionen, mit denen man einen der Wege erzwingt, und der Squash. Alle vier Wege führen zum selben Code in main. Sie unterscheiden sich nur darin, welche Historie entsteht.
