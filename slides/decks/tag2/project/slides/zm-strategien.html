Strategien: wie Git zwei Stände zusammenführt

StrategieWofürHinweis
ortZwei Branches mergenStandard seit Git 2.34, erkennt Umbenennungen
recursiveFrüherer StandardSeit Git 2.50 nur ein anderer Name für ort
resolveEinfacher 3-Way-MergeOhne Erkennung von Umbenennungen, selten nötig
octopusMehr als zwei Branches auf einmalBricht ab, sobald ein Konflikt entsteht
oursEinen Branch als erledigt markierenÜbernimmt nichts aus dem anderen Branch
subtreeProjekt in einem UnterverzeichnisGleicht die Verzeichnisstruktur an

Gewählt wird mit -s, etwa git merge -s ours. Im Alltag bleibt es bei ort, Git wählt die Strategie selbst.

Von SVN zu Git · Tag 2

Die Strategie ist das Verfahren, mit dem Git die Stände zusammenrechnet. Davon zu unterscheiden sind die Wege von der vorigen Slide, die bestimmen, welche Historie entsteht. Wer git merge mit zwei Branches aufruft, bekommt automatisch octopus. Die Strategie ours ist für abgelöste Branches gedacht, deren Inhalt bewusst verworfen wird.
