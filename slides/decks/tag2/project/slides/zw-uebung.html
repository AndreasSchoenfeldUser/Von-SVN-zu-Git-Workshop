Zusatzmodul · Git-Workflow

Ein vollständiger Release-Zyklus

  1. Legen Sie develop aus main an und schützen Sie beide Branches in GitLab.
  2. Entwickeln Sie zwei Features und einen Bugfix auf eigenen Branches und führen Sie sie per Merge Request nach develop.
  3. Taggen Sie das Entwicklungsrelease v1.1.0-dev.1.
  4. Festigen Sie das Release in release/1.1, taggen Sie v1.1.0 und führen Sie nach main und develop.
  5. Beheben Sie einen Fehler in Produktion über hotfix/1.1.1 und taggen Sie v1.1.1.

ZEIT

45 Minuten

ARBEITSFORM

Teams mit 3 bis 4 Personen

ERGEBNIS

Eine grafische Historie, die den ganzen Zyklus mit allen drei Tags zeigt.

Von SVN zu Git · Tag 2

Zum Abschluss die Historie mit git log --oneline --graph --all anzeigen und mit dem Überblicksbild des Moduls vergleichen.
