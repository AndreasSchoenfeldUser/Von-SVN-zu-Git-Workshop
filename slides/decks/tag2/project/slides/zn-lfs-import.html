Große Dateien nach Git LFS verschieben

Schritt 2: Die Migration schreibt die Historie um. Deshalb gehört sie vor die Arbeit im Team.

$ git lfs migrate import --everything \
>   --include="*.mp4,*.jpg,*.png,*.jar" --verbose
$ git lfs ls-files
3f9a2c41d7 * media/reiseziele/mallorca.mp4
8b1e07c2aa * media/reiseziele/kreta.jpg
$ git push --force --all
$ git push --force --tags
 
# Neue Dateitypen künftig über LFS
$ git lfs track "*.pdf"
$ git add .gitattributes
$ git commit -m "PDF-Dateien über Git LFS verwalten"

migrate import

Ersetzt die Dateien in der gesamten Historie durch Verweise und legt die passende .gitattributes an.

git lfs ls-files

Listet die Dateien in LFS mit ihrer Referenz (OID).

git lfs track

Trägt neue Muster in .gitattributes ein. Die Datei nicht von Hand bearbeiten.

Von SVN zu Git · Tag 2

Weil die Historie umgeschrieben wird, ist ein push mit --force nötig. In GitLab muss dafür der Schutz von main kurz gelockert werden. Danach klonen alle neu. Das Repository in GitLab wird erst kleiner, wenn die alten Objekte aufgeräumt sind (Housekeeping).
